# TrainTicket

12306 车票查询 + **无票时的替代方案分析**。

输入日期、出发地、到达地和时间窗，程序会列出符合条件的车次、各席别价格与运行时间。
当某趟车全程无票时，它会解析该车的经停站，找出可行的替代路线。

参考实现：`Joooook/12306-mcp`（TypeScript 项目，本项目把它的逻辑移植成了 Python）。

---

## 快速开始

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
```

**图形界面（推荐日常使用）**：

```bat
run-ui.bat
```

**命令行**：

```bat
run.bat -d 2026-10-02 -f 上海虹桥 -t 无锡 --time 06:00-12:00 -a
```

**查到的数据条目**：条件区下方实时显示本次查到多少条，分两行——第一行是条数汇总
（总数 / 有票 / 无票），第二行是日期、时段、站名和接口返回的车站组合数。
同城多站会让同一车次出现重复行，合并了多少条会一并说明，否则数字对不上。

**车站输入是边打字边检索的**：输入「上海」会列出 `上海`、`上海虹桥`、`上海南`…，
用方向键选、回车确认，也可以直接敲完整站名再点查询。填城市名会自动展开为该市全部车站。

**排序**：点任意列头即按该列升序，再点一次切降序，列头会显示 ▲/▼，并且视图会
自动回到顶部。按 `发车` 和 `最低价` 排序是最常用的两个。无票的车次整行标红、有票标绿。

**勾选框**：选中时方框里显示 `[√]`，未选是 `[　]`（全角空格占位，两种状态宽度一致不跳动）。

**风险提示默认收起**。每条方案下面的 `⚠` 行（票面发站与实际上车点不同、未乘区间
不退票款、补票可能被列车长拒绝等）信息量大但很占地方，所以默认隐藏。勾上
「显示风险提示」即可展开，切换即时生效、不用重新查询。**命令行版始终显示这些提示**。

**其他细节**：

- 表格和分析区之间的分隔条可以上下拖动，自己分配空间。
- 所有网络请求在后台跑，查询时窗口不会卡死，底部状态栏会显示进度。
- 车站表只在首次运行时联网下载一次，之后用本地缓存（`data/stations.json`）。
- 关掉分析开关就只查余票，不发额外的探测请求，快很多。

## 四种替代方案

| 策略 | 做法 | 风险 |
|---|---|---|
| **买短乘长** | 买 `出发站→中途站` 的票，上车后补票到目的地 | 补票段通常无座；列车超员时列车长有权拒绝补票 |
| **买长乘短** | 买一段比实际行程更长的票，在出发站上车、目的地提前下车 | 闸机可能不放行（票面发站不同）；未乘区间不退票款 |
| **同车分段** | 同一趟车买两张票，中途换座 | 两段座位可能不在同一车厢 |
| **候补** | 该车次支持候补时给出提示 | 只报告，**不代下单**（需登录 12306） |

### 关于「买长乘短」——它常常是唯一可行的那条

12306 对**热门区段**存在「**区间限售**」：把短区间锁死，只放开「始发站→终点站」的全程票。
实测 `D2928`（2026-10-02 上海虹桥→无锡）：

```
❌ 上海虹桥→昆山南   ¥22   全无票      ← 「买短乘长」走不通
❌ 上海虹桥→苏州园区  ¥33   全无票
❌ 上海松江→无锡     ¥66   全无票      ← 连全程起点到目的地也无票
✅ 上海松江→烟台     ¥419  无座有票    ← 唯一有票的（01→19 全程）
```

所以程序**三种购票策略都会试**，而不是只做「买短乘长」——只做一种的话，
这个案例上会一无所获。同时程序会把"探测过哪些区间"原样打印出来，
让你能判断它是真的确认没方案，还是根本没搜完。

```

-t, --to                到达地：同上
--time                  时间窗，如 06:00-12:00
--start / --end         时间窗（分开写）
--types                 车型过滤：GD 只保留 G/D；-K 排除 K
--exact-station         输入按车站解析，不做城市展开
--trains                只看指定车次，逗号分隔

-a, --analyze           强制开启替代方案分析

--no-buy-short          不分析「买短乘长」
--no-buy-long           不分析「买长乘短」
--no-split              不分析「同车分段」
--no-houbu              不提示「候补」

--max-requests          请求次数上限（默认 60）
--max-analyze-trains    最多分析几趟无票车次（默认 8）
--max-candidate-stops   每趟车最多探测几个中途落客站（默认 6）
--min-interval          请求最小间隔秒数（默认 1.2，硬下限 0.5）

--format                text（默认）/ json
--dry-run               只打印请求计划，不发请求
--refresh-stations      强制刷新车站表缓存
```

## 输出说明

**时间窗口径**：窗口作用于**你在出发站实际乘车的时刻**，不是票面始发站的时刻。
例如买「上海松江→烟台」的全程票，但你在上海虹桥上车，窗口比的是上海虹桥的 06:52。

**城市 vs 车站**：输入城市名（`上海`）会展开为该市全部车站；输入具体站名（`上海虹桥`）
只看该站。程序会在开头打印解析结果，例如：

```
[信息] 「上海」按城市解析，包含 4 个车站：上海、上海虹桥、上海南、上海西
```

**请求统计**：每次运行结束都会打印实际发出的请求数与缓存命中数。程序只读、未登录、
约 1 请求/秒，并在 `--max-requests` 处硬性停止，超限时会明确列出被跳过的探测项。

## 重要提醒

- **候补只做提示**。提交候补需要登录 12306，本程序只读、不代下单。
- **补票费用不做估算**。网上流传的"补票加收 50% 手续费"无法确证，
  程序不写任何具体数字或承诺，以 12306 官方规定和现场列车长为准。
- **买短乘长有被拒风险**。客流高峰时列车长有权拒绝补票并要求下车，
  程序会提示但不保证成功。
- **本程序不代购票**，只做查询与方案展示。

## 给维护者：12306 改版了怎么办

**先跑探针**：

```bash
.venv\Scripts\python.exe tools\schema_probe.py
```

它会打印行长分布、逐项校验字段锚点，并明确告诉你哪一项对不上。

### 为什么不能照抄网上的"固定下标表"

12306 的余票行是 `|` 分隔的长字符串。**可选字段为空时会被整个省略**，
所以同一批响应里各行的长度并不一致（实测见过 53~58 共 6 种）。照抄固定下标
不会报错，而是会**静默算出错误的价格**——用户是拿着这个结果去买票的。

本项目用「**头尾双锚定**」：

- **头部**（下标 0~19）位置稳定，直接按下标取。
- **尾部**一律写成 `len(行) - N`。删掉中间某个字段时，行尾字段的绝对下标和
  行长度会同时减 1，所以"倒数第 N 个"永远不变。
- **中间**那段字段下标会漂移，**不可依赖**，本项目不使用它们。

再加一条 **`seat_types` 自校验**：尾部有个字段正好等于价格位图里各席别码的顺序拼接
（`G7032` 的 `O,M,O` ↔ `'OMO'`）。两者不符 → 判定锚点失效 → **立刻报错，绝不猜**。
这是防止"静默输出错误票价"的最后一道闸门。

改动锚点只需修改 `src/config.py` 里的 `TAIL_*` 常量。

### 常见故障

| 现象 | 原因 | 处理 |
|---|---|---|
| `SchemaError: 席别自校验失败` | 尾部锚点失效 | 跑探针，更新 `config.py` 的 `TAIL_*` |
| `RiskControlError` 403/429 | 触发风控 | 等 5~15 分钟，`--min-interval 2` 降频 |
| 提示"路径已轮换，已自动切换" | 正常现象 | 无需处理，程序会读 `c_url` 自愈 |
| 大量"行解析失败" | 可能改版 | 跑探针确认 |
